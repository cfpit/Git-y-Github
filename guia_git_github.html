REPOSITORIOS CON GIT Y GITHUB

Guía integral paso a paso: conceptos fundamentales, trabajo local, gestión de ramas, subida remota y solución de autenticación.

📌 Conceptos Clave de Git

📍 Commits

Son los puntos en el tiempo (fotografías del estado de tus archivos). Cada commit guarda un avance concreto y seguro.

📈 Historial de cambios

Un conjunto de puntos formando una línea secuencial e inmutable a lo largo del desarrollo.

📜 Log

Una serie de puntos ordenados cronológicamente donde cada uno representa un avance con respecto al anterior.

📦 Staging Area

Área de ensayo: el lugar intermedio donde preparas exactamente las partes y archivos de tu progreso que deseas guardar.

🛠️ Flujo de Trabajo Local (Paso a Paso)

1

Crear carpeta del proyecto

Creamos y nos ubicamos en la carpeta de trabajo bici.

2

Inicializar Git en la terminal (Bash de VS Code)

Crea el repositorio local (la carpeta oculta .git):

git init
3

Configurar usuario del proyecto

Establece tu nombre y correo para firmar cada commit que realices:

git config --global user.name "Juan"
git config --global user.email "juan@gmail.com"

Para verificar la información ingresada:

git config --global user.email
Informa: juan@gmail.com
4

Crear archivo y consultar estado

Agrega a la carpeta bici el archivo primera_llanta.txt y ejecuta:

git status

Indica qué archivos se agregaron, modificaron o eliminaron (aparecerá en rojo como archivo sin seguimiento / untracked).

5

Mover cambios al Staging Area (Área de ensayo)

git add primera_llanta.txt

En el explorador de VS Code aparece la letra A (Added / Agregado).

Con git status ahora se muestra en verde (está preparado para el commit). Si no estuviera en stage, estaría en rojo.

Nota: Si quieres sacar el archivo del stage area y volver al principio: 
git rm --cached primera_llanta.txt
6

Agregar segundo archivo y crear el primer Commit

Creamos segunda_llanta.txt en la carpeta. Si hacemos un commit en este momento, solo se guardará el primer archivo (porque es el único en el Staging Area):

git commit -m "primera_llanta"

Luego, al hacer git status, solo verías el archivo segunda_llanta.txt pendiente, ya que el primero pasó formalmente del staging area al historial de commits.

7-8

Visualizar el historial de Commits (Log)

Muestra el código hash identificador, autor, fecha y mensaje del commit:

git log

Para ver el historial de forma más compacta (un commit por línea):

git log --oneline
Orden cronológico: Al agregar más commits, estos se listan siempre del más reciente al más antiguo.
9-10

Modificaciones, inspección con Diff y Staging

Si agregas texto dentro de primera_llanta.txt, inspecciona exactamente qué líneas cambiaron:

git diff

Para volver a subir estas modificaciones al staging area:

git add primera_llanta.txt
11

Quitar archivos del Staging Area y agregar todo

Forma moderna de quitar un archivo del stage area sin perder los cambios del archivo:

git restore --staged primera_llanta.txt
Atajo para agregar todo: Para pasar todos los archivos nuevos y modificados juntos al staging area: 
git add .
12-13

Moverse en el tiempo (Viajar entre Commits)

Para viajar a una versión anterior (fotografía) usando el hash de un commit:

git checkout <hash_commit>

Para regresar a la actualidad (último commit de la rama principal):

git checkout master
# o de forma moderna:
git switch master
14-15

Comparar commits y descartar cambios locales

Ver las diferencias exactas entre dos momentos del historial:

git diff <hash1_commit> <hash2_commit>

Si modificaste un archivo que aún no commiteaste y quieres revertirlo a su estado original (deshacer cambios sin usar Ctrl+Z):

git restore primera_llanta.txt

O para descartar cambios no guardados en todos los archivos a la vez:

git restore .

🌿 Trabajo con Ramas (Branches)

🌿

Creación, navegación y fusión de ramas

1. Ver en qué rama estamos actualmente:

git branch

2. Crear una nueva rama:

git branch segunda

Al volver a escribir git branch ahora aparecerán ambas ramas (master y segunda).

3. Cambiar a la nueva rama:

git checkout segunda
# o con el comando moderno:
git switch segunda

4. Hacer cambios en la rama secundaria y guardarlos:

Modificamos segunda_llanta.txt y creamos un commit exclusivo de esta rama:

git add segunda_llanta.txt
git commit -m "agregar linea en segunda rama"

Revisamos con git log --oneline: observamos que master llega hasta un determinado punto del historial y segunda continúa con el nuevo commit.

5. Unir ramas (Merge):

Unir ramas es llevar los commits de una rama a otra. Para traer los cambios de segunda hacia master, primero nos posicionamos en master:

git switch master
git merge segunda

Se abre el editor para confirmar el mensaje de unión, el cual genera un nuevo commit de merge.

6. Ver el historial de forma gráfica:

git log --oneline --graph

7. Eliminar la rama que ya fue integrada:

git branch -d segunda

☁️ Subida a GitHub y Repositorio Remoto

☁️

Conectar con GitHub y Push

1. Crear cuenta y repositorio en GitHub:

Creamos el repositorio en GitHub (ejemplo: https://github.com/cfpit/Fondo.git).

2. Ver remotos configurados:

git remote

3. Vincular el repositorio remoto:

git remote add origin https://github.com/cfpit/Fondo.git

4. Subir los cambios:

git push origin master
¿Qué significa? origin es el alias del servidor remoto en GitHub y master es la rama de nuestro repositorio local que deseamos enviar.
!

Solución: Error de Autenticación al hacer Push

remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed for 'https://github.com/cfpit/Fondo.git/'

Causa: GitHub no admite tu contraseña normal de inicio de sesión para operaciones de Git. Requiere un Personal Access Token (PAT).

  1. Generar el Token en GitHub:
    Ve a tu perfil en GitHub → Settings → Developer Settings → Personal access tokens → Tokens (classic) → Generate new token (classic).
    Asigna un nombre, marca el permiso repo y genera el token. Copia el código generado (ghp_...).
  2. Borrar credenciales viejas en Windows:
    Abre el menú Inicio → busca Administrador de credenciales → Credenciales de Windows → sección Credenciales genéricas → busca git:https://github.com → haz clic en Quitar.
  3. Volver a hacer Push:
    Ejecuta nuevamente: 
    git push origin master
    - Si abre ventana: selecciona "Sign in with your browser" o ingresa el Token generado.
    - Si lo pide en consola: Usuario = tu usuario de GitHub; Contraseña = pega el Token.
Al hacer refresh en GitHub, ¡verás todo tu repositorio local subido correctamente al remoto!
⬇️

Bajar cambios del remoto al local (Git Pull)

Para probar la sincronización inversa, agregamos un archivo README.md directamente en la web de GitHub.

Luego, para traer y fusionar esos cambios al repositorio local:

git pull origin master

Al completarse, verás cómo aparece automáticamente el README.md en tu proyecto local de VS Code.
